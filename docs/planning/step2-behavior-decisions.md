## B-02 计划期与历史

规则有稳定ruleId和不可变revisionId；计划期key=(ruleId, revisionId, intendedLocalDateTime)，以公历本地日期和分钟精度表示，秒为00。正式期有独立taskId及唯一key；提醒eventId=(key, "primary")，提前量改变不制造第二次主提醒。单次任务使用taskId与日程版本作身份。

提前量属于独立ReminderPolicy，不靠创建新RuleRevision更改：只重算尚未发出的事件，已claimed/sent/uncertain的主事件不重发。规则修改若替换出同一ruleId、同一本地计划钟点，则建立旧新key别名，并继承旧事件的已处理状态；不能通过新版本号绕过去重。若计划钟点确实改变，视为新计划，预览同时列出取消旧计划和新增计划。Task本身保存当期提前量快照；修改单期提醒不改变其他期或规则。

计划期是规则计算结果。可持久化它的通知定位信息及提醒状态，但不把它加入正式任务表。通知点击：正式期存在则打开该期；尚未到期则打开“计划于…到期，届时生成记录”卡片，只允许查看规则、编辑规则或停止周期，不允许完成尚不存在的期。中间期已跳过则显示“本期未建立任务记录”；旧版本已取消显示“计划已变更”，可进入当前规则。已删除记录显示“该记录已删除”。启动后也按这个身份解析。

改规则先冻结旧版本未来提醒，取消所有旧版本尚未到期计划事件（含已发送通知的旧点击目标标作失效）；已生成期的未发提醒按自身快照处理。删除单期取消其未发提醒并保留tombstone；删除周期取消未来事件，已有未完成期保留正常提醒；选择删除全部历史时取消全部相关未发事件。恢复旧期只改完成状态，显式设置不再提醒，不改变任何其他期。

调度每次计算最新已到期计划点L，而不是循环补建所有遗漏点；L若已存在、已删除或已被处理则不向前找替代；中间遗漏区间记跳过说明。长停机采用锚点直达算法，回拨不降低已处理区间。检查/创建/提醒状态更新在同一主进程串行队列执行。

停止周期后重新开启：保留原日/周/月锚点及全部历史，以重新开启时刻作为新有效下界，只取不早于该时刻的下一计划点；停用期间不补Task或通知。若恰好在计划点开启则当场生成，同key已有记录/删除标记仍不重建。开启导入副本也遵循此规则。修改生效边界采用“旧版本含保存瞬间，新版本严格晚于保存瞬间”，保证同一瞬间不被两版各建一期；新建/重新开启的初始下界则包含当下。

## B-04 提醒生命周期（V-LIFE）

到期墙钟字段决定日常展示与当前时区解析；createdAt/updatedAt为UTC审计时间。时区改变重新解析未来和未完成记录的本地到期时间，已完成历史保留生成时区/偏移供查阅。倒计时按解析后瞬间计算，日历组按当前本地日期计算。

正常扫描发送到达提醒时间的主事件一次；前跳/时区变更只触发正常扫描，不生成“时间变化”通知。前跳错过的有效提醒汇总，回拨不重置已处理身份。夏令时按DT11/12确定；调度用墙钟，闲置/超时用单调时钟，系统恢复时直接检查锁定。

| 情况 | 正式任务补算 | 系统通知与入口 |
| --- | --- | --- |
| 正常运行/托盘 | 每次最新到期，连续运行能逐期保留 | 提醒到点一次；点击任务或计划期 |
| 休眠恢复 | 只补最新到期，既有期不删 | 对休眠区间所有仍有效且未提醒的事件汇总一次，DDL页“提醒记录”可展开，包括未建任务的中间期 |
| 暂停恢复 | 暂停只停通知，任务照常生成 | 暂停区间有效未发事件汇总一次；仍暂停时休眠恢复只登记待发 |
| 彻底退出/崩溃后重启 | 只补最新到期 | 退出区间事件标作应用内待查看，不补系统通知；首页展示逾期与今日到期；未来提醒正常继续 |
| 休眠期间进程终止 | 按重启处理 | 不伪装成连续休眠进程补发 |

汇总按截止时间升序展示，各项可定位；100条/页，长区间分批计算并存区间游标，不能把大量中间事件变成任务。完成或删除的期在发送前过滤；已恢复旧期一律不再次提醒。隐私开关开启时汇总只显示数量。

持久状态pending→claimed→sent或failed/uncertain，另有suppressed/cancelled/inAppOnly；发送前持久claimed，重启不再次调用通知API。OS通知与文件不能组成事务：崩溃在调用边界时标uncertain，应用内仍可查看，避免声称绝对“恰好一次送达”。API明确失败显示“系统通知未送达，请在提醒记录查看”，不自动反复重试；系统免打扰导致不展示同样不伪称用户已读。汇总batchId与成员关系一起保存，重复resume事件不重复发。

普通导入/快照恢复不导入另一机器的投递账本；本机账本按身份/别名保留终态。所有恢复进来的已到期事件标为inAppOnly或suppressed，未来事件按下一提醒点调度；未来期的提前点已过但截止尚未来到时，导入本身只展示应用内提示，不补系统通知。确认提交后仍暂停提醒的保持暂停；已取消/完成/删除/手动恢复旧期不复活提醒。崩溃后用持久扫描游标区分“退出区间”与启动后首次到点；休眠恢复只在同一存活进程的生命周期区间执行补发。

## B-05 列表、教学周

未完成正式任务分组顺序：逾期(dueInstant < now)；今日(尚未逾期且本地日期=今日)；未来7天(明日00:00 ≤ dueLocal < 今日+8天00:00)；更晚。精确到期瞬间属于今日，随后为逾期。各组截止时间升序、创建时间升序、ID作稳定末级排序；完成历史按completedAt倒序。计划卡片单独显示，不混进正式任务数量。首页最多每组5条并提供“查看全部”。

学期结束为week1Start+7×总周数，区间左闭右开。手动起点非周一拒绝并提示最近周一供主动选择。时段采用[start,end)，09:00相接不冲突；特殊时间必须成对，开始00:00—23:59，结束00:01—24:00且start<end；24:00只表示本日结束端点，不能作为开始或跨入次日的时刻。跨午夜课程须拆两天，例如周一23:00—24:00、周二00:00—01:00，不能自动扩展星期或教学周。节次1—13且结束≥开始，节次表各段开始<结束且按序不重叠；跨多节实际为首节开始至末节结束。特殊时间完全覆盖推导时间。课程有效周先求范围与单双周交集，再交星期、实际时间；冲突保存后动态重算标记，解决冲突即移除。

## B-06 密码簿锁定交互

仅密码簿页可信键盘、点击、编辑、搜索、复制等主动操作重置5分钟；鼠标经过、后台计时、其他页面活动不重置。默认显示15秒后隐藏，可设置时长；隐藏不等于锁定。切换普通页继续计时；最小化、托盘、系统锁屏/休眠立即锁定。

密码簿编辑用明确“保存”按钮（普通笔记仍自动保存）；编辑页显示“锁定时未保存修改会丢失”。锁定立即遮盖并丢弃未提交编辑、清除渲染状态、使sessionToken失效。复制在主进程重新检查解锁代次；锁定后不再复制，已有剪贴板仍按30秒及内容未替换检查清除。备份/改主密码/恢复准备阶段锁定就取消；若已进入仅密文的不可取消提交阶段，允许完成原子提交，界面仍锁定，结果下次解锁查看。主密码/KDF工作不能延长可见解锁；取消后迟到结果不得写入。

## B-07 导入与计数

模式边界：合并以当前业务数据为底，仅加入接受的输入，文件中没有的本地记录保留，冲突逐条四选项。覆盖以校验后的输入业务数据为全量，缺席的现有普通记录会移除；确认页逐类列出新增、替换、将移除数量和明细，再二次确认。覆盖不静默套用合并选择，也不清除密码簿、本机图片文件、快照或本机通知终态；快照恢复采用相同的业务全量替换契约。覆盖用户在最终确认前取消则整个业务状态不变。

预览期间只保存临时选择，不修改业务；合并的四选项逐条显示全部变化字段。“保留现有”表示此身份选本地版本供导入引用；“跳过本条”忽略该输入，引用只能落到已有合法本地身份，缺失依赖须继续解决，否则不能提交。

全部选择后显示计划新增/替换/副本/跳过数量，确认再加独占写锁，检查baseRevision未变化，生成保护副本并统一提交。预览期间本地变化则重新计算受影响差异，不静默复用旧选择。取消整次导入：业务状态不变，清除暂存；提交前可取消，提交开始后显示“正在完成，请稍候”，失败自动回滚。

统计以输入实体（标签、分类、笔记、随手记、规则版本、期记录、课程、时段、学期、配置记录）计数，并分类型列出。成功=实际落地新增/替换/副本；跳过=完全相同/保留现有/跳过本条，分原因；依赖自动重映射不另计实体。整次失败时成功=0；已尝试后回滚的条目单列“已回滚”，未尝试列“未执行”，直接出错列“失败”；不将所有条目重复算失败。文件解析失败时失败文件1、实体总数未知。取消状态不冒充失败。

统计恒等式：输入实体总数=成功+跳过+失败+已回滚+未执行，互斥归类。整组写入/保护副本失败等无对应输入实体的错误，另计“操作失败1次”，不虚构失败实体；覆盖移除的本地实体另列“移除”，不加进输入实体成功数。取消时显示“已取消，落地0条”，仍可查看预览计划数量但不把它当成功。
