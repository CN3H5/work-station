## 一、实现统一普通存储服务

### 数据格式与目录

沿用 Step 2 的目录和封装设计：

- 普通数据使用 `ordinary/current.json`。
- 保留一代 `previous.json` 供恢复，不占用户快照名额。
- 快照最多 7 份。
- 事务保护副本独立保存，不参与快照轮换。
- 密码簿和图片文件不进入普通存储、快照或恢复操作。

实现 `schemaVersion=1`、稳定 UUID、递增 revision、UTC 审计时间、规范化 JSON 和 SHA-256 校验。区分完整文件的 `contentHash` 与普通业务投影的 `snapshotHash`。

按 D-02 建立普通数据类型、空数据工厂和校验器，校验字段、重复 ID、关联关系及周期期次唯一性；本阶段只负责保存与校验，不执行日期调度或课程冲突计算。

本机通知账本、图片索引和可迁移业务数据使用明确的投影函数隔离。恢复普通业务时保留本机资源索引及提醒终态，不能通过整体替换重新激活旧提醒。

读取前检查大小，解析时拒绝重复键、危险结构键、不支持版本、错误字段和哈希不一致。未知或损坏数据不得被初始化为空文件覆盖。

50 MiB 作为普通文件软预算，达到时提示；100 MiB 和 100000 实体作为本阶段硬上限，超限拒绝保存并保留旧版本。

### 主进程唯一写者

建立串行写入队列；渲染进程不能提交任意完整文件、文件路径或通知账本。

内部存储服务提供：

- 打开、读取状态与只读查询。
- 携带 `baseRevision`、`clientMutationId` 的提交。
- 等待待保存操作完成的 `flush`。
- 快照查询、校验和恢复。
- 版本迁移注册与启动恢复。

并发修改遇到旧 revision 返回 `CONFLICT`，不静默采用最后写入覆盖。重复 mutation 返回原结果；同一 mutationId 携带不同内容须拒绝。将最近 256 个成功 mutation 的去重信息随普通文件原子提交，排除在业务快照之外；超过保留窗口的旧请求按 revision 冲突处理。

新增面向渲染端的能力仅限存储状态、受限偏好保存、快照列表和确认恢复。返回统一结果及错误码，例如 `CONFLICT`、`VALIDATION`、`IO_FAILED`、`UNSUPPORTED_VERSION`、`RECOVERY_REQUIRED`，不得返回内部路径、正文日志或堆栈。

## 二、实现保存、事务与恢复

### 自动保存

实现可复用的 500ms 防抖保存控制器，并通过一个真实的非敏感偏好字段验证完整流程，不提前开发笔记页面。

保存状态包括：已保存、保存中、保存失败、冲突、只读恢复。

- 主进程完成写盘、校验及持久提交后，界面才能显示“已保存”。
- 保存失败保留当前编辑内容，提供重试。
- 连续编辑期间旧请求返回，不能把新草稿误标为已保存。
- 离开编辑区和正常退出前执行 flush。
- 正常退出时保存失败，提供重试、返回应用和确认放弃；异常终止按恢复协议处理。

### 事务提交

实现 D-03 的单普通文件事务：

1. 串行检查输入、revision 和目录边界。
2. 写入并校验新版本及旧版本保护副本。
3. 持久写入 PREPARED journal。
4. 同卷替换 current，保留可恢复旧版本。
5. 回读校验后持久写入 COMMITTED。
6. 返回成功，再清理事务临时文件。

journal 只能包含应用推导的固定目标类型及文件标识，恢复时不能按其任意路径执行读写。

首次初始化也必须可恢复：区分真正的新目录、初始化中断和已存在的数据缺失。不能仅因 current 不存在就认定用户没有数据。

### 启动与异常恢复

存储恢复结束前不开放业务写入。

- 未提交事务恢复旧状态。
- 已提交事务核验新状态后完成清理。
- COMMITTED 后清理失败只登记待清理，不回滚成功保存。
- journal 损坏、新旧版本均不能验证时，进入只读恢复状态并保留原文件。
- 当前文件损坏且无可判定事务时，提示用户选择有效 previous 或快照，不静默恢复或清空。
- 恢复动作可重复执行；恢复过程再次中断后仍能继续。

本阶段先完成普通文件事务。图片、密码簿的多文件业务事务不提前实现，但接口与文档必须明确适用范围。

## 三、实现快照、版本检查和最小恢复界面

### 最新 7 份快照

落实已确认策略：

- 每天第一次普通业务内容变化且成功保存后生成。
- 导入或快照恢复前生成保护快照；本阶段为未来导入实现内部准备接口。
- 内容相同可复用，不逐键生成。
- 通知账本或纯审计更新时间改变，不制造业务快照。
- 快照成功后才能完成轮换，最终最多保留最新 7 份。
- 轮换不能删除进行中事务的保护副本。

快照失败不否定已成功保存的业务内容，单独显示“快照未生成”，并允许稍后重试；当天触发标记只在成功后更新。

快照列表根据实际封装校验重建，损坏项明确标记，不能仅凭文件名认定有效。

### 快照恢复

恢复前展示时间和范围，二次确认，先保护当前有效数据，再执行普通事务。

当前数据损坏时，先保留损坏原件；无法生成有效当前快照不应阻止用户恢复已验证快照。不得把损坏文件当成正常快照。

恢复仅处理普通业务投影，保留本机提醒终态、图片文件及密码簿；恢复旧任务不能补发历史系统通知。

只增加支持上述操作的最小状态和恢复界面，不展开完整九页导航或视觉设计。

### 版本迁移

首个真实格式保持 schemaVersion=1，建立逐版本迁移管线、迁移前保护、结果校验和事务切换能力。

本项目没有正式发布的旧格式，不凭空把测试格式声明为用户历史格式。使用仅供测试注册的旧版样本验证迁移成功、失败及中断；生产环境不注册该虚构格式。

遇到未来版本或没有迁移路径的版本，拒绝写入并保留原文件。

## 四、测试、验收与交付

### 必须执行的测试

使用独立测试目录、虚构数据和可控时钟。故障测试同时覆盖注入异常和独立子进程被终止后的实际重启恢复。

重点覆盖：

- 初始化中断、正常保存、重启读取和多请求串行提交。
- revision 冲突、重复 mutation、旧保存响应与新草稿竞态。
- new、old、journal、替换、回读、COMMITTED、cleanup 各阶段中断。
- 写入失败、空间不足、Windows 文件占用及恢复再次中断。
- 错误 JSON、重复键、错误类型、重复 ID、悬空关联、错误哈希和未来版本。
- 同日多次、跨日、时间回拨、业务未变及仅运行账本变化。
- 连续产生 9 份不同快照后保留最新 7 份。
- 快照失败后的重试、恢复前保护失败、轮换不影响事务副本。
- 普通保存与恢复完全不触碰虚构密码簿和图片文件。
- 实际 Electron 的合法调用、恶意参数、未授权窗口和受限保存接口。

对子进程终止、文件占用和模拟 ENOSPC 分别标明证据；模拟测试不能写成已完成真实断电或物理磁盘满测试。

记录 1万、10万实体及 2 MiB 笔记样本的打开、校验、保存、快照耗时和内存，报告 p50/p95。常规保存目标约 1 秒，超出时处理或明确说明，不伪造指标。

### 验证工具与 Skill

使用项目 `electron-offline-verification` 技能复核新增接口及网络边界。保留 Step 3 已修复的失败门槛，新增报告必须检测证据缺失、失败和未执行状态。

按新增存储验证结果扩展统一验证入口；代码变化后运行相关存储测试及完整 `npm run verify`。证据绑定源码摘要，不把旧摘要对应的通过记录当作新版本结果。

需要实际 Windows 界面操作时，读取当前 computer-use Skill 及其指导文件后使用。skill-creator 只用于有实测复用证据的流程，本阶段不强制创建技能。

Windows 10、安装包、便携版、物理断网和长期待机继续保留原验证门槛，当前 Windows 11 结果不能替代。

### GitHub 与文档交付

本任务授权提交并推送 Step 3 修复及 Step 4 成果到现有私有仓库，分别组织提交和 PR。检查通过后合入主分支；失败时保留工作分支并修复，不强制推送、不发布 Release。

更新 README 的实际数据文件、保存状态、快照、恢复及未加密说明；在实施文档目录交付 Step 4 的存储接口说明、故障验证记录和下一阶段交接。重大设计调整同步对应规划文档，不改变已确认的用户行为。

最终汇报实际完成范围、通过与未执行项、恢复限制、文件链接、GitHub PR，以及是否具备进入 T05 的条件。本阶段交付结束后停止，不自动开发后续业务模块。
