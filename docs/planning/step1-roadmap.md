3. **M3 本地基础**：T03–T05 满足存储、安全、UI 基础。无正确保存/迁移前，不将功能原型当可用产品。
4. **M4 功能完整**：T06–T13 集成；备份范围等所有数据类型稳定后完成 T12；首页/全局搜索依赖各模块且必须验证密码隔离。
5. **M5 发布就绪**：T14 所有强制案例通过，T15 文档、两类包及哈希齐备，再按项目授权发布。

## 3. GitHub 与源码流程

- Step 1 不创建仓库、不提交/推送，不为调研克隆或运行候选。
- 后续选型核实优先用已连接 GitHub 插件只读查看，限定影响可行性的事实；记录链接、版本/提交、日期和未验证项，不重复大规模调研。
- 实现阶段按可独立说明的改动组织提交；完成对应检查后提交，说明变化和验证结果。
- 每个阶段结束推送工作分支；对应验收通过后合入主分支；里程碑产出构建，正式发布遵循当时授权。
- 仓库为私有 `work-station`；源码中排除真实笔记、密码、备份、日志、个人配置及构建产物；人工测试数据用虚构内容。私有可见性不代替加密或数据隔离。
- 发布包及校验值放 GitHub Release；记录构建对应的提交，保留可复现脚本和锁文件。最终地址以实际创建结果为准，不预造仓库 URL。
