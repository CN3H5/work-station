# Step 3 交接

交付续审：2026-10-28。范围仅T03，版本1.0.0，未发布。最终检查状态与提交地址将在源码同步完成时写入本节。

## 已实现

精简Electron/TypeScript/Vite工程，主进程、沙箱preload、本地渲染、共享契约及测试分离。生产只暴露健康状态接口；资源协议受打包清单和内容哈希限制；权限默认拒绝；未知目录/高版本标识拒绝覆盖。正式目录契约固定为`%LOCALAPPDATA%\WorkStation`，开发、预览和自动化使用各自隔离根，单实例恢复已有窗口。

已有可控时钟、故障注入契约及隔离测试工具，但没有普通数据事务实现。Windows条件剪贴板模块已经在当前系统技术验证，不开放给渲染器，也没有完整密码簿。依赖锁定、审计、许可再生与本地打包配置入口已建立。

## 验证与复现

从README安装与构建。已有环境执行`npm run verify`，查看[统一验证摘要](evidence/verification-summary.json)与[逐项验证](step3-validation.md)。开发用`npm run dev`；本地生产资源验证用`npm run start:preview`。`npm start`才进入正式目录，不用它测试用户资料。

本阶段本地核心检查为7项基础断言、14项实际Electron检查、5项剪贴板技术验证，以及生产资源离线模拟与进程网络观察。以最新源码哈希关联的摘要为最后依据，不将业务占位或未执行系统计为通过。

## 保留门槛与影响

- Windows10环境缺失：需要补该系统以及两包实际分发测试，不能在最终发布前豁免。
- 离线可用通过Chromium网络模拟验证；没有物理禁网测试。网络观察为10秒及当前骨架，不能替代托盘30分钟和未来业务的V-OFFLINE。
- 原生模块当前仅作技术验证，不进入产品包；T09接入时需实现30秒计时、退出有限清除和占用提示，重新验证两系统/两包。
- 17个开发依赖没有独立许可文件，清单保留其声明与README；正式分发前继续核对打包工具与成品许可。本阶段不发布Release。
- 没有托盘、全局快捷键、自启、提醒、普通存储、迁移、导入、密码簿或九页交互。当前关窗退出是工程骨架行为，后续完整产品仍按既定托盘设计实现。

## T04/T05 进入条件与建议顺序

当前Windows11的安全骨架验证成功且工作成果完成私有仓库同步后，具备开始T04和T05的工程条件。先做T04唯一写者、目录所有权、恢复协议与故障注入，再做T05基础导航、焦点和错误状态。可以共享接口契约，不能以UI“已保存”替代事务成功。

T04必须覆盖H-02的V-STORE、V-SNAPSHOT及相关恢复边界；T05以960×640及小工作区为初值，保留缩放、中文输入法、键盘与错误状态门槛。日期、导入和加密留到各自任务，继续沿用Q-01—07、U2/U3。此聊天到Step3结束，不自动开展业务开发。
