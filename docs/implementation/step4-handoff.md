# Step 4 验收与下一阶段交接

日期：2026-10-29。范围：普通单文件存储、偏好自动保存、快照、版本检查和恢复。未开发笔记、DDL、课表、密码簿、图片迁移、普通备份导入导出或全部清除。

## 实现与协议

接口、投影、错误码、事务与适用范围见 [存储接口](step4-storage-api.md)。故障覆盖、进程终止和实际Windows操作见 [故障验证](step4-fault-validation.md)。本轮修复了损坏JSON恢复无法建事务、旧mutation回执变化、文件占用后的重试、恢复缺失current误初始化，以及时间回拨后的快照顺序问题。

普通文件 schemaVersion=1；主进程串行唯一写者。规范化payload的contentHash与排除本机账本和纯审计时间的snapshotHash分离。最近256个mutation的固定回执原子持久化。current、previous、最多7份快照、独立事务保护分别管理。普通数据明文，密码簿和图片本体从不参与普通保存或恢复。

损坏current和不可判定事务保留原件，用户可明确选择验证过的previous/快照。COMMITTED之后清理失败不回滚；下一次写入先完成清理。未知/未来版本拒写。迁移仅测试注册虚构版本0，生产不注册。恢复旧任务抑制提醒，保留可验证的本机通知终态和资源索引；current/previous的本机索引都损坏时无法重建丢失索引，但图片本体不删除。

## 验证证据

统一入口扩为11步，包含类型检查、56项Node测试、45项独立存储证据、构建、原生构建、16项实际Electron检查、5项剪贴板检查、网络观察、离线模拟、3项原生UI证据绑定与性能。最终结果以 [统一源码绑定记录](evidence/verification-summary.json) 为准。存储明细见 [storage-latest](evidence/storage-latest.json)，UI实际操作见 [storage-ui](evidence/storage-ui.json)。新增报告拒绝数量缺失、失败、跳过、异常退出或源码绑定过期。

性能使用1万、10万实体和2 MiB笔记各5次，分别记录打开、验证、保存含每日快照、单独快照创建及复用耗时，以及每阶段后的RSS；给出p50/p95。原始样本见 [storage-performance](evidence/storage-performance.json)。RSS是进程累计采样，不是单操作的隔离峰值。整文件严格解析、图校验、多次持久化及快照使大数据保存超过约1秒目标；这是明确记录的性能限制，不宣称高容量交互性能已经达标。

## 验收边界和T05

T04完成条件是成功保存后能重启恢复；关键故障点得到完整旧版本、新版本或明确只读状态；不静默清空；快照与密码簿隔离；证据对应当前源码。本轮围绕这些条件补齐测试与修复，检查全部通过后可以进入T05。T05仍应保留高容量保存耗时提示，后续有实际业务数据分布后再优化，不能取消完整性和事务检查换取速度。

Windows10、安装/便携版、物理断网、物理磁盘满、真实断电及长期待机仍未执行，不由当前Windows11开发运行时替代。ENOSPC是故障注入；子进程终止是真实操作系统进程终止，不是物理断电。网络结论只覆盖当前实现和10秒观察时段。普通恢复不保证找回无有效副本的数据；本地JSON与SHA-256不提供加密或对恶意修改的认证。
